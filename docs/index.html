A local, in-memory text mailbox for two running AI agents.

Agent Mailbox

把两个正在运行的 AI Agent 接到同一个本机文本信箱。一边写完，另一边读取；用户看着双方的文字，也可以暂停、补充要求或结束。

它不运行模型。Cursor、Codex 或其他能执行命令的 Agent 继续用自己的工具，只通过 Python 客户端收发 UTF-8 文本。消息留在应用进程的内存里，退出后消失，不写入磁盘。

源代码：github.com/xuwupeng2000/agent-mailbox

程序坞和菜单栏

Mac 应用放在程序坞里，运行时菜单栏也有一枚帽子标记。下面两张是 2026-10-26 从这台 Mac 的实际界面截取的，不是图标源文件。

打开之后

Mac 应用监听 127.0.0.1:9777。窗口左右各一张卡片，对应两位参与者。还没有人写信时，卡片保持空白。

一位 Agent 开始读取

Agent 执行一次阻塞的 wait。队列里还没有新消息时，它的卡片出现橙色提示，名字来自它自己的 --as。对方 write 之后，这条等待才会拿到完整正文。等待期间不调用模型。

两边都写完

每条消息以 <<<END>>> 结束。写完的正文出现在对应卡片上，另一位 Agent 用 wait 取走发给自己的那一条。

按轮查看记录

「查看两人对话」打开记录。每一轮有分隔线，方便回头找某一段。记录里也可以按关键词搜索；搜索只过滤显示，不改信箱里的内容。

用户能做的事

  • 展开「发起双 Agent 对话」，填写两位不同的名称、共同任务和 1–20 轮。A 先发言，双方各回复一次算一轮。
  • 暂停后续投递，或把补充要求送给下一位发言者。已经交给 Agent 的文字不能撤回。
  • 结束时，两位 Agent 各自向 user 报告自己完成的动作；两份报告都到齐后会话停止。
  • 关掉主窗口后，Mac 应用仍留在菜单栏并继续听端口。

Agent 怎么接入

在仓库根目录执行。名称用界面里指定的名字；受控会话要带上收到的 SESSION。

python3 agent_mailbox.py wait --as cursor --timeout 30

python3 agent_mailbox.py write --to codex --from cursor --session <本次会话编号> <<'MESSAGE'
这里填写回复正文。
MESSAGE

回复之后再执行一次 wait，对方的下一条 write 才能把这边唤醒。完整规则在仓库的 AGENT_README.md。
